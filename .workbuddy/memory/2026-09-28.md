## v2.0.4（Build 2609280009）真根因找到：中文输入法吞掉注入按键 → 改 WM_CHAR 直投
- 用户 v2.0.3 真机复测：进度能走（映像名前台判定生效）、面板日志显示"检测到 WPS 在前台"，但 WPS 页面依旧空白，自动/手动两种模式都不出字。
- 现场诊断方法（关键经验，本机即真机、WPS 就在本机，可直接写脚本现场注入+回读验证）：
  1. 枚举 WPS 窗口/进程 → tasklist 输出是 GBK，subprocess 需 bytes + decode("gbk")；
  2. 自己拉起 wps.exe blank.docx 做全流程实验；WPS 主窗口类名是 KLiteMainWindowShadowBorder（非 Chrome_WidgetWin_0），文档画布是子窗口类名 _WwG；
  3. 用 Ctrl+A/Ctrl+C 回读文档内容判定按键是否真到达（SendInput 返回 True ≠ 事件到达目标）；
  4. 排除法：WPS 未提权（UIPI 排除）、SendInput 全部返回成功（结构体打包正确）、Ctrl 组合键可达（通路正常）。
- 根因：中文 IME 把 KEYEVENTF_UNICODE 注入字符整个吞进组合窗口（EA 语系 IME 通病，AutoHotkey 文档亦有记载）；跨进程 ImmAssociateContext 对 WPS 窗口返回 NULL 关不掉 IME；顶层 shadow border 窗口不接字符（焦点在其上时 WM_CHAR 也无效）。
- 修复（wps_driver.py）：type_char 改为 WM_CHAR 直投——get_focus_hwnd() 用 GetGUIThreadInfo 查 WPS 线程真实键盘焦点子窗口（_WwG 画布；焦点在顶层框架时用 EnumChildWindows 找 _WwG），字符按 UTF-16 码元（增补字符拆代理对）PostMessageW(WM_CHAR) 直投画布，句柄缓存每 200 字刷新；\n/\t 走 SendInput VK_RETURN/VK_TAB（控制键 IME 不吞；实测 WM_CHAR 0x0D 在 WPS 不生成段落标记）；SendInput Unicode 与剪贴板 Ctrl+V 保留为三级兜底。
- 真机端到端验证通过：生产 type_char 写入"摸鱼文书v2.0.4修复验证ABC123\第二行中文OK"，Ctrl+A/C 回读全文命中含段落符。
- 冒烟扩至 36/36（新增 WM_CHAR 直投断言、回车走 SendInput、代理对、失败回退链）。mock SendInput/PostMessageW 必须用普通函数（_send_input_list 会设 argtypes，绑定方法不可设）。
- 打包注意：给了 .spec 就不能再传 --onefile/--noconsole/--icon（makespec options not valid）；distpath/workpath 用全新目录绕沙箱批量删除拦截。v2.0.3 归档 history/，v2.0.4 部署根目录（191261320 字节）；诊断脚本与旧构建目录已清理。
